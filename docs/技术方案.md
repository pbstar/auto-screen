# Auto Screen —— 可视化桌面操作 Agent 技术方案

> 版本 v0.4 ｜ 2026-10-23 ｜ 技术栈 TypeScript

## 1. 项目定位

一句话：**看到一个窗口，说一句话，它替你点鼠标、敲键盘，把事做完。**

- **目标**：在 macOS 与 Windows 上，用户指定一个目标窗口并输入一段自然语言任务，程序循环「截屏 → 视觉模型理解 → 调用鼠标/键盘工具 → 再截屏验证」，直到任务完成；全过程有可视化界面，可观察、可暂停、可接管。
- **形态**：Electron 桌面应用，本地运行，模型走 DeepSeek API（`deepseek-flash`）。
- **不区分应用类型**：浏览器页面和原生应用一视同仁——对 Agent 来说都只是目标窗口里的像素和坐标，同一套工具覆盖两类场景。
- **一期不做**（避免复杂化）：
  - OCR / 模板匹配的固定流水线
  - 操作录制回放（列入二期）
  - 插件市场、多 Agent 协作
  - 后台无人值守批量执行
  - Linux 适配（保留抽象，只验证 macOS 与 Windows）

## 2. 核心思路与参考项目的关系

参考项目 [xyks-helper](https://github.com/pbstar/xyks-helper) 是一个**单场景固定流水线**：

```
截图 → 按固定坐标裁剪 → OCR 识别数字 → 计算答案 → 鼠标绘制
```

它验证了「Node 截图 + 模拟鼠标」这条路可行，但只适用于一个固定界面、一个固定任务。

本项目把它换成**通用的感知-决策-执行闭环**：

```
截图 → 视觉大模型理解界面 → 输出工具调用（点击/输入/按键/滚动）→ 执行 → 再截图 → 循环
```

它的截屏与鼠标能力可以参考，但 OCR 和固定坐标裁剪在一期直接去掉——视觉模型本身就完成了「看懂屏幕」这一步。

## 3. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 桌面壳 | Electron（最新稳定版） | TypeScript 全栈、原生能力齐全、生态成熟；Tauri 更轻但要写 Rust，不符合 TS 技术栈要求 |
| 工程脚手架 | electron-vite | 主进程 / preload / 渲染进程一套 Vite 构建，HMR 好用 |
| 界面 | React + TypeScript + MUI（Material UI） | 直接使用 Material Design 的组件与主题体系，不引入 Tailwind，也不自研样式基建；按需引入，保持界面清爽 |
| 状态管理 | Zustand | 轻量，只存任务、步骤、配置三块状态 |
| 模型调用 | `openai` SDK（OpenAI 兼容）+ `deepseek-flash` | 原生多模态，图像与文本同一接口；支持 function calling、流式输出与自动上下文缓存；成本远低于同档闭源模型 |
| 屏幕采集 | node-screenshots | 窗口枚举、窗口坐标、窗口截图一次拿全，省掉 desktopCapturer 与窗口 bounds 的匹配；N-API 预编译，macOS / Windows 均支持 |
| 图像标注 | `@napi-rs/canvas` | 给截图叠加标尺与虚线网格；N-API 预编译产物，不需要 electron-rebuild |
| 鼠标键盘 | `@nut-tree-fork/nut-js` | 社区维护分支，Apache-2.0、有预编译产物；macOS 与 Windows 都支持 |
| 文本输入 | 剪贴板 + `Mod+V`（Electron clipboard） | 中文、emoji、长文本比逐键输入稳得多；macOS 用 Cmd、Windows 用 Ctrl |
| 配置存储 | electron-store | 存界面偏好（步数上限、动作间隔、上次窗口等），不存密钥 |
| 配置与密钥 | dotenv + `.env` | API Key、Base URL、模型名走环境文件；官方 Key 和代理网关只差一个 URL |
| 打包 | electron-builder | 同时产出 macOS dmg 与 Windows nsis 安装包 |

**为什么自己维护工具循环？**
DeepSeek 的 Chat Completions 接口只接受调用方声明的 function tools，没有内置的 computer use 工具；模型不会自己执行鼠标键盘，所有动作都必须由我们定义、执行并把结果回传。这原本是为了可视化、安全拦截和中文日志，现在也是唯一选择——工具 schema、执行逻辑和界面展示因此完全自持，模型层仍可通过 adapter 替换。

**模型与接口的基本事实**（以官方文档为准，写代码前复查一次）：

- 模型 ID `deepseek-flash`，OpenAI 兼容接口 `https://api.deepseek.com`，用 `openai` SDK 调用即可。
- 图像放在 `user` 消息的 `content` 数组里，`{"type": "image_url", "image_url": { "url": "data:image/png;base64,...", "detail": "high" }}`。
- 大图会被压缩到约 1300×1300 的总像素规模，单图最多计 1024 tokens；这一点直接决定了截图和坐标策略（见 5.1）。
- 思考模式通过 `thinking` + `reasoning_effort` 控制；多轮工具调用时，assistant 消息里的 `reasoning_content` 必须原样回传，不能手工裁剪。

职责划分很直接：

- **Renderer 不碰系统能力**，只负责展示与发指令。
- **Main 里的 Agent Loop 是唯一决策中枢**，串行执行，任何时刻只有一个动作在跑。
- **core/ 三件套**是纯能力层，不依赖模型，可以被手动测试（一期第一步就是手动验证它们）。

## 5. 关键模块设计

### 5.1 屏幕采集与坐标体系

这是最容易踩坑的地方，规则先定死：

1. **采集目标**：用户在界面上选择窗口（`node-screenshots` 的 `Window.all()`），之后每步只用 `captureImageSync()` 截这个窗口。截自己的问题天然消失；窗口的 `x / y / width / height` 也来自同一个库，坐标换算不需要再匹配另一套窗口信息。
2. **送给模型的是缩放图**：DeepSeek 会把大图压缩到约 1300×1300 的总像素规模（小图则放大到约 544×544），单图最多计 1024 tokens。截图按长边约 1280px 发送，正好落在有效分辨率内，也不会无谓增大请求体。工具返回给模型时**同时带上图片尺寸**，并约定：**所有坐标都是这张截图里的像素坐标**。
3. **图上带标尺与网格**：发给模型的截图先叠加刻度——顶部、左侧各一条 10px 小刻度的标尺，画面内每 100px 画一条虚线并标注坐标数字，左上角为 (0,0)。网格线用低透明度细虚线，不遮挡界面元素，让模型直接「读格取坐标」而不是估算。界面预览展示同一张标注图，人和模型看到的标尺读数完全一致。
4. **坐标精度 10px**：所有工具坐标的最小单位是 10px，必须是 10 的倍数。模型读格给值；工具端统一做一次 `Math.round(v / 10) * 10` 对齐，并把**实际落点**写回工具结果，模型能立即发现偏差并修正。
5. **内部换算**：`click` 工具收到截图坐标后，按 `scale = 窗口逻辑宽 / 截图宽` 换算成系统逻辑坐标，再交给 nut.js。模型不需要理解 Retina、缩放、窗口偏移，这些全部在 `core/screen.ts` 里消化。
6. **权限**：macOS 需要「屏幕录制」和「辅助功能」，缺失时界面顶部提示并跳转系统设置；Windows 没有系统级授权，但如果目标窗口以管理员权限运行，本应用也要以管理员身份启动，否则鼠标和键盘事件会被系统拦截。

```ts
interface Capture {
  image: Buffer        // PNG，已缩放并叠加标尺与网格
  width: number        // 缩放图宽（模型坐标系）
  height: number
  scale: number        // 截图坐标 → 屏幕逻辑坐标 的比例
  windowId: number
}
```

**坐标换算只在两个地方发生**：`capture()` 产出 scale，`input` 工具消费 scale。其他模块一律用截图坐标，避免到处乘以 2。

**网格常量只有一份**：`core/grid.ts` 里定义 `MINOR = 10`、`MAJOR = 100`，截图标注、界面预览、系统提示词都引用这组常量。系统提示里明确告诉模型：原点在左上角，小刻度 10px，虚线大格 100px，输出的坐标取 10 的倍数。

**跨平台坐标**：macOS 的 Retina 与 Windows 的每显示器 DPI 缩放（125% / 150% / 200%）都会让逻辑坐标和物理像素不一致。`scale` 统一由 `core/screen.ts` 根据窗口所在显示器的 `scaleFactor` 与截图实际尺寸计算，其他模块不感知平台差异。

**小目标定位**：模型真正「看清」的分辨率有限，工具栏图标、小字号按钮容易点偏。策略是先用 `screenshot(region)` 裁剪目标区域，再发一张局部图——局部图会被模型放大到有效分辨率，定位精度明显提高。系统提示里明确要求：目标小于约 40×40px 或文字看不清时，先裁剪确认，再点击；点击一律落在元素视觉中心。裁剪图上的标尺继续标**原图绝对坐标**，因此模型给出的始终是全图坐标，工具层不需要二次换算。

### 5.2 动作执行

`core/input.ts` 对 nut.js 做一层薄封装，只暴露 6 个语义动作：

```ts
click(x, y, button = 'left', count = 1)
move(x, y)
scroll(direction, amount)
drag(from, to)
typeText(text)          // 默认走剪贴板 + Mod+V
pressKeys(combo)        // 如 'mod+c'、'enter'、'escape'；mod 在 macOS 为 Cmd、Windows 为 Ctrl
```

三点约定：

- `typeText` 默认**剪贴板粘贴**：先 `clipboard.writeText`，再 `Mod+V`，随后恢复原剪贴板内容。中文输入法、emoji、长文本都稳。保留 `逐键输入` 作为备选（可在设置里切换），用于剪贴板被占用的场景。
- 每个动作执行后固定 `sleep(actionDelayMs)`，默认 150ms，给界面反应时间；设置项可调。
- **坐标先对齐再执行**：工具层把坐标取整到 10px 网格后才交给 `core/input.ts`；`input` 只负责执行，不关心网格和缩放。

### 5.3 Agent 循环

串行、可中断、有上限。核心伪代码：

```ts
import OpenAI from 'openai'

const client = new OpenAI({
  baseURL: 'https://api.deepseek.com',
  apiKey: config.apiKey,
})

async function runTask(task: Task, ctx: RunContext) {
  const messages: ChatCompletionMessageParam[] = [
    { role: 'system', content: buildSystemPrompt(ctx.enabledSkills) },
    { role: 'user', content: task.prompt },
  ]

  for (let step = 0; step < task.maxSteps; step++) {
    const shot = await screen.capture(ctx.windowId)
    messages.push(imageMessage(shot))                 // user 消息，附带图片尺寸说明

    const stream = await client.chat.completions.create({
      model: 'deepseek-flash',
      messages,
      tools: toolSchemas,                             // OpenAI function 格式
      tool_choice: 'auto',
      parallel_tool_calls: false,
      max_tokens: 8192,
      stream: true,
    })

    const message = await collectStream(stream)       // 聚合流式增量
    messages.push(message)                            // reasoning_content 必须原样保留
    if (!message.tool_calls?.length) break            // 只返回文字 = 任务完成

    for (const call of message.tool_calls) {          // 串行执行
      const result = await runTool(call, ctx)
      messages.push({ role: 'tool', tool_call_id: call.id, content: result.text })
    }
  }
}
```

设计要点：

- **串行执行工具**：鼠标操作天然有先后，请求里设 `parallel_tool_calls: false`，即便模型一次给出多个调用也逐个执行。
- **思考模式**：用 `thinking` + `reasoning_effort` 开启，按任务复杂度在 `low` / `high` / `max` 中选择；assistant 消息（含 `reasoning_content`）必须原样写入历史，字段缺失会返回 400。
- **图片历史控制**：每步都会产生一张新截图。只保留最近 2 张为图片块，更早的替换成一行文字（如「第 3 步截图：点击了 (120,340) 之后」）。DeepSeek 单图最多 1024 tokens，成本压力不大，但上下文长度仍要控制。
- **上下文缓存**：DeepSeek 自动命中前缀缓存，不需要手动打缓存标记；只要 system、tools 前缀保持字节稳定（不混入时间戳、随机 ID）即可享受缓存价。
- **流式输出**：思考与文字增量推给界面，用户能看到它在「想什么」，避免长时间无反馈。
- **终止条件**：模型返回纯文本、达到步数/时长上限、用户点停止、连续 3 次同一动作失败。
- **失败反馈**：工具报错时把错误原因写进对应的 `tool` 消息回传，让模型自己换策略，而不是直接中断任务。

### 5.4 内置工具集

工具即「手和眼」，全部在主进程注册。Schema 用 zod 定义，转成 OpenAI function 格式（`{ type: 'function', function: { name, description, parameters } }`）后随请求下发。

| 工具 | 参数 | 说明 |
|---|---|---|
| `screenshot` | `region?` | 截取目标窗口（可指定区域），返回图片 + 尺寸；小目标先裁剪再定位 |
| `click` | `x, y, button?, count?` | 单击/双击/右键，坐标基于截图并取整到 10px |
| `move` | `x, y` | 移动鼠标（用于悬停展开菜单），坐标规则同上 |
| `type` | `text` | 输入文本（默认剪贴板粘贴） |
| `key` | `combo` | 按下组合键，如 `mod+shift+t`；`mod` 在 macOS 为 Cmd、Windows 为 Ctrl |
| `scroll` | `direction, amount, x?, y?` | 在指定位置滚动，坐标规则同上 |
| `drag` | `fromX, fromY, toX, toY` | 拖拽，起点与终点坐标规则同上 |
| `wait` | `ms` | 等待界面响应（≤5000ms） |
| `list_windows` | — | 列出当前可操作窗口，用于任务开始时确认目标 |

所有带坐标的工具只接受截图坐标系下的值，执行前统一按 10px 网格对齐；工具结果里返回**实际落点**和当前缩放比例，模型可以据此判断有没有点偏。

工具统一契约：

```ts
interface ToolDef<I> {
  name: string
  description: string        // 写给模型看，说明何时用、坐标含义
  schema: ZodType<I>
  handler(input: I, ctx: RunContext): Promise<ToolResult>
}
```

`ToolResult` 固定为 `{ text: string; image?: Buffer; isError?: boolean }`。注册表负责：schema 校验 → 安全检查 → 执行 → 记入时间线 → 回传结果。所有副作用集中在这一层，方便统一加日志、限流、dry-run。

**刻意不做**的工具：`open_app`、`exec_shell`。这类「系统级动作」风险高、平台差异大，一期用统一的界面操作覆盖；确有需要（比如启动浏览器）可以由用户先手动打开窗口，再让 Agent 接管。

### 5.5 技能系统（Skills）

技能是**给模型的操作知识**，工具是**可执行的手脚**，两者分开：

- **工具**：原子能力，代码实现，参数严格。
- **技能**：一段 Markdown 操作指南，告诉模型这类任务该按什么步骤做、注意什么、怎么自查。

技能格式（`skills/form-fill/SKILL.md`）：

```markdown
---
name: 表单填写
description: 按顺序填写表单类界面，适合登录、设置、信息录入
match: 填写 / 输入 / 表单 / 注册
---

## 适用场景
界面中有多个输入框需要依次填入数据时使用。

## 操作步骤
1. 先截图，确认所有目标字段都完整可见；不可见先滚动。
2. 逐个点击输入框 → 输入内容 → 截图确认文字正确落入目标框。
3. 每个字段填完后不要马上点提交，全部检查一遍再提交。
4. 出现校验错误时，读取错误提示，修正对应字段后重试，最多两次。

## 注意
- 输入中文一律使用 type 工具（内部走剪贴板），不要逐键敲。
- 点击前确认输入框边框已高亮，避免把内容输到上一个框。
```

- 启动时扫描 `skills/`，解析 frontmatter，渲染到左侧技能库。
- 一期由**用户勾选**技能 + 始终注入一个「通用操作」技能；不做自动路由，减少不确定性。
- 系统提示里的技能内容按固定顺序拼接，保证前缀缓存命中。
- 技能里描述位置优先用网格相对位置（如「左数第二个大格、第三行」）；确实要写坐标时用 10px 对齐值，并注明它只在当前窗口尺寸下有效。
- 内置三个技能即可：`通用操作`、`表单填写`、`重复操作`（列表逐项处理）。

### 5.6 可视化界面

布局（Material 风格，信息层级清晰，不做多余装饰）：

```
┌──────────────────────────────────────────────────────────────────┐
│  任务：____________________________        [开始] [暂停] [停止]   │
├────────────┬────────────────────────────────┬────────────────────┤
│ 技能库      │  10px 标尺 · 100px 虚线网格     │  执行时间线         │
│  ☑ 通用操作 │  ┌──────────────────────────┐  │  ① 截屏            │
│  ☐ 表单填写 │  │ ┊   ┊   ┊   ┊   ┊   ┊   ┊ │  │  ② 点击 (120, 340) │
│  ☐ 重复操作 │  │ ┊ 目标窗口 + 点击标记    ┊ │  │  ③ 输入 "张三"      │
│            │  └──────────────────────────┘  │  ④ 截屏            │
│ 历史任务    │  缩放 1:1  ☑ 网格   目标 Chrome │  ⑤ 点击 (400, 520) │
│  · 昨天…    │                                │  ...               │
├────────────┴────────────────────────────────┴────────────────────┤
│ 权限 ✓     步数 3/30     耗时 12s      $0.004                       │

```

样式统一由 MUI 主题承载：主色、圆角、间距走 theme token，个别布局用 `sx` 微调；不引入 Tailwind 或其他全局 CSS 框架，也不自研组件库。

要素说明：

- **实时预览**：每步执行完把截图推到界面，叠加点击位置标记（红色圆环 + 编号），用户一眼看出它在点哪。
- **标尺与网格**：预览区顶部和左侧显示 10px 刻度标尺，画面叠加 100px 虚线方格，原点在左上角；鼠标悬停显示对齐到 10px 的 `(x, y)`。工具栏可开关网格；「取点模式」下点击画面会复制坐标，编写技能、调参数时直接粘贴。预览默认 1:1 显示，窗口放不下时等比缩放到适屏并标注比例；网格与读数始终按截图坐标计算。
- **时间线**：每条记录包含序号、工具名、参数、耗时、执行结果、该步截图缩略图；点击可放大。
- **状态与成本**：步数、耗时、累计 token 与费用，让成本可见。
- **暂停/接管**：暂停后用户可手动操作界面，再继续；停止立即 abort 循环。
- **目标窗口选择**：开始前弹出窗口列表（含缩略图），选错窗口是这类应用最常见的事故来源。
- **状态栏**：显示权限状态（macOS 分屏幕录制与辅助功能，Windows 显示是否为管理员权限）、步数、耗时与累计费用。

### 5.7 安全与可控

桌面自动化有真实的破坏力，一期就要有的底线：

1. **全局停止热键** `mod+alt+shift+x`（macOS 为 Cmd、Windows 为 Ctrl；避开 Windows 的 `Ctrl+Shift+Esc`，那是任务管理器），任何情况下立即中断当前循环。
2. **前台窗口校验**：每次鼠标动作前确认目标窗口仍在前台；被切换到其他应用时暂停并提示，而不是盲点。
3. **步数与时长上限**：默认 30 步 / 10 分钟，可配置。
4. **危险区域提示**：点击落在屏幕边缘 40px 内的 Dock / 任务栏 / 菜单栏区域时记录警告（不阻止，但时间线标黄）。
5. **dry-run 模式**：只计算并显示将要执行的坐标与动作，不真正落鼠标，用于调试技能。
6. **操作日志落盘**：每次运行的截图、动作、模型输出存到 `userData/runs/<runId>/`，出问题可复盘。

### 5.8 配置与密钥

模型相关配置全部从环境文件读取，改完重启生效，不在代码里写死：

```dotenv
DEEPSEEK_API_KEY=sk-xxx
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-flash
```

- 官方 API Key 和代理网关都支持：换网关只需要改 `DEEPSEEK_BASE_URL`，代码不用动。
- 开发环境读项目根目录 `.env`；安装包首次启动在 `userData/` 下生成 `.env` 模板并读取同一份配置。
- `.env` 加入 `.gitignore`，仓库只提交 `.env.example`。
- 界面只显示 Key 的末四位和当前模型的连通状态，不提供明文查看；日志里禁止出现完整 Key。
- 启动时校验三项配置，缺失或连通性失败时在顶部状态栏给出明确提示，不进入 Agent 循环。

│  ├─ preload.ts               # contextBridge 暴露 typed API
│  ├─ config.ts                # 读取 .env、校验配置
│  ├─ ipc/handlers.ts          # 渲染层 ↔ 主进程通道

├─ src/
│  ├─ core/
│  │  ├─ screen.ts             # 窗口枚举、截图、缩放、坐标换算
│  │  ├─ input.ts              # nut.js 封装

## 9. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| macOS 权限缺失 | 截图黑屏 / 点击无效 | 启动即检测，界面明确引导；`systemPreferences.isTrustedAccessibilityClient`（仅 macOS） |
| Windows 目标窗口以管理员运行 | 点击与输入被系统拦截 | 检测前台窗口权限，提示以管理员身份重启本应用 |
| 原生模块（nut.js / node-screenshots）在 Electron 中加载失败 | 装完跑不起来 | 两者都是 N-API 预编译产物；装完先跑 M1 自检，确认 `require` 成功；仍失败时再用 `@electron/rebuild`，CI 固定 Node/Electron 版本 |
| 坐标偏差（Retina、Windows DPI、多屏） | 点偏 | 坐标统一在截图坐标系内，只有 `screen.ts` 做换算；多屏取窗口所在屏的 `scaleFactor` |
| 模型看错界面、反复无效操作 | 死循环、浪费时间 | 连续 3 次同动作失败即终止；每步要求模型先描述看到什么再动作 |
| 每步截图累积 | 上下文变长、响应变慢 | 只保留最近 2 张图；更早的降级为文字；system/tools 前缀保持稳定以命中自动缓存 |
| 图像压缩导致小控件点偏 | 点击失败或误点 | 小于约 40×40px 的目标先裁剪局部图再定位；点击元素视觉中心；连续失败即终止 |
| 网格遮挡界面细节 | 模型识别变差 | 虚线低透明度、只画 100px 主网格；小目标仍用裁剪图；预览区可一键关闭网格 |
| Windows 独占全屏 / DRM 窗口截图为黑 | 无法识别画面 | 检测截图近黑时提示改用窗口模式，明确不支持独占全屏 |
| 模型给出非 10px 坐标 | 点击偏差 | 工具层统一对齐并回报实际落点；系统提示强调坐标取 10 的倍数 |
| 思考模式下未回传 `reasoning_content` | 接口返回 400 | assistant 消息原样写入历史，不手工裁剪字段 |
| 界面变化导致技能失效 | 技能过时 | 技能只写策略不写死坐标；坐标一律来自当步截图 |
| 误操作（点错按钮、删数据） | 不可逆后果 | 前台校验、步数上限、停止热键、dry-run；重要任务建议先跑 dry-run |
| 未签名安装包被系统拦截 | macOS 需手动放行，Windows 触发 SmartScreen | 一期在文档说明；正式分发前补代码签名与公证 |
