# Auto Screen 技术方案

> v1.0 ｜ 2026-10-26 ｜ TypeScript

## 1. 项目定位

一句话：**看到一个窗口，说一句话，它替你点鼠标、敲键盘，把事做完。**

- **形态**：Electron 桌面应用，本地运行，模型走 DeepSeek（`deepseek-flash`，OpenAI 兼容接口）。
- **循环**：截屏 → 视觉模型理解 → 调用鼠标/键盘工具 → 再截屏验证，直到任务完成。全过程可视、可暂停、可接管。
- **最终目标**：把 Web 系统与桌面应用的操作手册写成技能（`SKILL.md`）导入，由 Agent 照着执行。这类任务步骤远超 30 步，还包含「等 5 分钟再点下一步」「每 3 分钟重复一次」这样的固定节奏，所以项目的第一要求是**稳定**，其次才是省 token、减延迟。
- **不区分应用类型**：浏览器页面和原生应用一视同仁，对 Agent 来说都只是目标窗口里的像素和坐标。

## 2. 架构

```
┌──────────────────── Renderer（React + MUI） ────────────────────┐
│  窗口选择 / 实时预览与网格 / 任务输入 / 技能勾选 / 时间线 / 日志 │
└──────────────────────────────┬──────────────────────────────────┘
                    contextBridge │ IPC（typed）
┌──────────────────────────────▼──────────────────────────────────┐
│                          Main Process                           │
│  Agent Loop（感知-决策） ──▶ Tool Registry（11 个内置工具）      │
│         │                        │                              │
│         ▼                        ▼                              │
│  Prompt 组装（通用 + 规则 + 技能） core/screen · core/input      │
│  LLM 封装（DeepSeek）           core/pointer · core/safety       │
│  Rule / Skill Loader（rules/ · skills/）                         │
│  RunStore（日志与截图落盘）                                     │
└─────────────────────────────────────────────────────────────────┘
```

职责边界：

- **Renderer 不碰系统能力**，只负责展示与发指令。
- **Agent Loop 是唯一决策中枢**，串行执行，任何时刻只有一个动作在跑。
- **core/ 是纯能力层**，不依赖模型；`src/agent` 不直接调系统 API。
- 坐标换算只发生在 `core/screen.ts`（截图 → 屏幕物理像素）和 `core/input.ts`（物理像素 → nut 单位），其它模块一律用截图坐标。

## 3. 坐标体系

最容易踩坑的一层，规则固定，改动前先看这里。

1. **采集**：用户选窗口，之后每步用 `node-screenshots` 的 `captureImageSync()` 截这个窗口，坐标与尺寸同源。
2. **缩放**：长边缩到 1280px 再发给模型。DeepSeek 会把大图压到约 1300×1300 总像素、单图最多计 1024 tokens，1280 正好落在有效分辨率内，也不会无谓增大请求体。
3. **网格**：截图叠加 10px 刻度标尺 + 虚线主格，每条主格线标绝对坐标。主格步长自适应：长边 <640px 用 50px，否则 100px。**画布不加页边距**，图片左上角严格映射 (0,0)——试过把刻度挪到图外留白里，模型会读歪一个边距，提示词里说明也没用。截图不铺底色格，半透明色块会压低界面本身的对比度。
4. **样式同源**：界面预览（SVG）与截图标注（canvas）共用 `src/shared/grid.ts` 的 `GRID` / `GRID_STYLE`，含线色、标签字号、基线距离。两边各写一套数值会慢慢长歪。
5. **落点回显**：每次指针动作后，在下一张截图上画青色小十字标出落点（14px，带深色描边）。模型据此判断「我点在这儿、目标在那边」，点偏了按偏移量修正。
6. **10px 对齐**：所有工具坐标必须是 10 的倍数，统一由 `snapToGrid()` 对齐并裁剪到画面内；这个函数是唯一实现，工具、准星、预览读数都走它。工具结果回写实际落点，模型能立刻发现偏差。
7. **权限**：macOS 需要「屏幕录制」「辅助功能」，以及「自动化」中允许控制 System Events（用于把目标窗口激活到最前）。Windows 没有系统级授权，但目标窗口以管理员身份运行时，本应用也要以管理员身份启动。

## 4. Agent 循环

`runAgent → 规划 → runLoop（≤ MAX_STEPS）→ runStep`：暂停闸门 → 截图标注 → 追加历史 → 请求模型 → 执行工具；模型宣布完成时再走一次核对。

设计要点：

- **一步一个动作**：每次回复只允许一个 tool_call，执行完立刻截图，模型用新截图确认效果再决定下一步。曾放开成一次给多个动作（8 个点击连发）来省调用次数，实测全部盲执行，结果算错后模型还宣布成功——稳定性代价太大，已回退。循环里保留保护：万一模型仍给出多个调用，前一个失败时后面的直接跳过并说明原因。
- **先定流程**：正式执行前先做一次不带工具的高思考调用（带当前画面）：判断界面状态，给出 3~8 步流程与「完成标准」。流程作为一条 user 消息注入会话，之后所有步骤共享这段前缀，缓存不受影响；画面与流程不符时以画面为准。这一步的用量同样计入时间线。
- **思考分档**：规划与最终核对用 `high`，执行步只在失败恢复（工具失败或核对未通过）后用 `high`，其余用 `low`。策略写死在循环里，不做配置。每步都是独立请求，`reasoning_effort` 不进提示词前缀，换档不影响缓存；实际档位随用量写进运行日志。
- **图片历史**：每步一张截图，只保留最近 2 张为图片块，更早的替换成一行文字（不破坏 assistant/tool 配对）。`reasoning_content` 必须原样回传，缺失会返回 400。
- **上下文缓存**：DeepSeek 自动命中前缀缓存，system 与 tools 前缀保持字节稳定即可；每次请求的 `prompt_cache_hit_tokens` 记进日志，用来核对真实成本。
- **串行执行**：鼠标操作天然有先后，请求里不开启并行工具调用，即使模型给多个也逐个执行。
- **暂停与接管**：`PauseGate` 在步骤边界挂起，暂停期间不截图、不调模型、不落鼠标。运行中每 120ms 采样一次光标，偏离基线即判定人工接管并自动暂停；Agent 自己操作期间忽略采样。任务结束或手动终止后立即停止采样，收尾沉淀期间不会再产生暂停事件。
- **人工确认**：`ask_user` 会让循环原地等待。提问期间把本应用带到前台、压住人工接管检测（用户要点选项，否则会被判成接管），回答后先激活目标窗口再放行，避免下一步截到本应用。回答作为工具结果回传模型，用户也可以跳过；没有超时，终止会立即取消等待。
- **最终核对**：模型不再调用工具（宣告完成）时，再用一次不带工具的高思考调用，带任务、流程、模型的结论和最后一张截图，要求返回 `{"ok": …, "problem": …}`。不通过就把差距作为 user 消息回灌、下一步提升到高思考强度；连续两次不通过以 `unverified` 收尾（界面红字显示差距，也不触发自动沉淀）。解析不出结论时按通过处理，避免格式问题卡死任务。
- **完成后沉淀**：任务卡上的「自动沉淀」开关（默认关闭）打开后，只有任务自然完成（`completed`）且步数 ≥ 3 才在收尾时多请求一次模型：只喂文本轨迹（每步的工具、参数、结果，以及当时对界面的判断）与目标窗口标题，不喂截图。产出的 `SKILL.md` 写进 `skills/auto-<时间>/`，撞名加序号、绝不覆盖已有技能，也不自动勾选。`finished` 事件先发，界面照常回到空闲；沉淀失败只在任务卡下方提示，不改变任务结果。蒸馏期间 `active` 不释放，用户终止只会取消这次沉淀、不发事件。
- **终止收敛**：模型返回纯文本且核对通过、达到步数上限、用户点停止、连续 2 次工具失败、同一指针动作连续 3 次重复，都会结束；核对连续两次未通过以 `unverified` 结束。致命错误（目标窗口不存在、权限缺失）第一次就终止，不再回传模型浪费 token。
- **步数与等待**：`MAX_STEPS = 300`，只为兜住死循环。三种等待各司其职：`wait` 固定等待（上限 1 小时）；`wait_for_change` 在本机轮询画面差异，变化即返回，等待期间不调模型；`wait_until` 等到当天某个时刻（如 17:01）。三者都是分段等待（500ms 一跳）：暂停立即生效且暂停时长不计入，终止立即退出，每 10 秒向界面报一次「已等待 00:30 / 05:00」；超过 `wait` 上限会直接报错，不静默裁剪。跨天或每天重复不做，那属于定时任务。
- **画面变化检测**：`wait_for_change` 的基准是本步模型看到的那张原始截图（截图时顺带采样指纹，见 `agent/watch.ts`），所以对手在模型思考的两三秒里落子也不会漏。检测把窗口缩到 320 宽、按 8px 分块比较平均灰度：两块超过 8 或单块超过 24 判定变化，随后等画面连续两帧一致（最多 800ms）再返回。实测这个粒度能识别 20px 的棋子和 12px 的状态文字，光标闪烁、单个小圆点不会误判。

## 5. 工具

工具是 Agent 的「手和眼」，全部在主进程注册。Schema 用 JSON Schema 写，转成 OpenAI function 格式随请求下发。

| 工具 | 参数 | 说明 |
|---|---|---|
| `click` | `x, y, button?, count?` | 单击 / 双击 / 右键 |
| `move` | `x, y` | 只移动不点击，用于悬停展开菜单 |
| `drag` | `fromX, fromY, toX, toY` | 按住左键拖拽 |
| `scroll` | `x, y, direction, amount?` | 在指定位置上下滚动，1~10 格 |
| `type` | `text` | 输入文本到当前焦点（剪贴板 + Mod+V，中文稳定） |
| `key` | `combo` | 组合键，`mod` 在 macOS 为 Cmd、Windows 为 Ctrl |
| `wait` | `ms` | 等待 0~3600000ms（1 小时），暂停不推进、终止立即退出 |
| `wait_for_change` | `timeoutMs?` | 本机轮询画面差异，变了就返回；默认等 120 秒，最多 1 小时 |
| `wait_until` | `at` | 等到本地时刻（`HH:mm[:ss]`），到点或超过一分钟即报错 |
| `ask_user` | `question, options?, multiple?` | 向用户提问并等待回答，2~4 个选项或自由输入，可跳过 |
| `list_windows` | — | 列出当前可操作窗口 |

契约：

```ts
interface ToolDef {
  name: string
  description: string                  // 写给模型看：何时用、坐标含义
  parameters: Record<string, unknown>  // JSON Schema
  execute(input: Record<string, unknown>, context: ToolContext): Promise<ToolResult>
}
```

`ToolResult` 只有 `{ text }`；失败一律抛错，由循环统一转成 `isError` 回传模型。副作用（日志、时间线、失败收敛）集中在循环层，工具只做动作。

**新增工具**：在 `src/agent/tools/` 新建一个文件导出 `ToolDef`，再在 `tools/index.ts` 的数组里加一项即可。模型定义与界面工具列表都从这个数组生成，不需要改别处。

## 6. 规则与技能

- **规则 = 始终生效的硬约束**（不越出目标窗口、不可撤销动作只按任务要求做、验证与凭据交给用户、如实汇报）；**技能 = 按任务勾选的操作手册**（「怎么做」）。两者都注入系统提示，优先级：规则 > 手册 > 通用说明。
- **内置规则**写在 `src/agent/rules.ts`，随应用发布，不能关闭或覆盖；调整只改这里的常量。
- **自定义规则**放 `rules/<名字>.md`，每次任务都会加载，不参与勾选。frontmatter 可选（`name`、`description`），不写就用文件名；按文件名排序注入，前缀稳定。只需要补约束、不需要改代码：

  ```markdown
  ---
  name: 生产环境禁点
  description: 顶部工具栏的批量删除不要碰
  ---
  - 顶部工具栏的「批量删除」按钮任何情况下都不要点。
  ```

- **技能的形态**：`skills/<id>/SKILL.md`，`id` 即目录名，frontmatter 只有 `name` 与 `description`（单行 `key: value`，不引 YAML 依赖），正文就是手册。示例：[skills/calculator/SKILL.md](../skills/calculator/SKILL.md)（计算器）。
- **加载**：`src/agent/rules.ts` 与 `src/agent/skills.ts` 在任务启动时扫描目录，缺失目录、没有正文或没有 `name` 的文件直接跳过，不阻塞应用。
- **注入顺序**：通用说明（坐标、工作方式、完成条件）→ `## 规则`（内置在前、自定义在后）→ `## 操作手册`（勾选的技能，按目录名排序）。规则在技能之前，属于缓存稳定前缀，不随任务勾选变化；不勾选技能时前缀完全一致，缓存命中不受影响。
- **不做自动匹配**：选错手册比不选更糟，路由交给用户。
- **改动生效**：打开「技能」或「规则」胶囊时重新扫描目录，改完 `SKILL.md`、`rules/*.md` 立刻能在浮层里看到；已经开跑的任务用的是启动时的快照。
- **技能写法**：位置用网格相对位置（如「左数第二个大格、第三行」），不写死坐标；每步都用新截图核对；易错点写进「注意」（例如计算器不接受粘贴）。
- **规则写法**：一条规则一件事，只写必须做或禁止做什么，不写操作步骤（步骤属于技能）。
- **目录位置**：开发时读项目根目录 `rules/`、`skills/`，打包后读 `userData/`；一期还没做把内置内容复制到安装目录。
- **自动沉淀**：任务完成后由模型整理的手册，frontmatter 同样只有 `name` 与 `description`；目录名取自手册名（去掉路径非法字符、最长 40 字，重名加序号），名字不可用时回退 `auto-<yyyyMMdd-HHmm>`。手册只写通用流程，不写本次的收件人、账号、文件名、数值等具体数据，具体值用「任务给定的…」描述；目录不会被自动勾选，删掉目录即可丢弃。

## 7. 运行记录

每次运行一个目录 `runs/<时间>-<runId 前四位>/`（开发时在项目根目录，打包后在 `userData/`）：

- `run.log`：任务、模型、每步截图尺寸、模型输出、工具调用与结果、用量（含缓存命中）、结束原因；`sk-` 形式的串自动脱敏。
- `step-01.png`…：每步发给模型的标注截图，时间线点开大图时读取。

`meta.json` 存任务、起止时间与结束原因，供界面列出历史运行。

## 8. 配置

模型配置只从环境文件读取，改完重启生效：

```dotenv
DEEPSEEK_API_KEY=sk-xxx
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-flash
```

- 换代理网关只需改 `BASE_URL`，代码不用动。
- `.env` 不入库，仓库只提交 `.env.example`；日志不出现完整 Key，界面不提供明文查看。
- 缺 Key 时界面提示，且不允许开始任务。

## 9. 界面

紧凑工具型布局：左侧实时预览 + 网格 + 坐标读数，右侧只有两块——顶部的任务卡（任务输入、开始/暂停/终止，步数与用量）、下方铺满剩余高度的执行时间线。技能、规则与工具这类不常改的配置收进输入框下方的三个小胶囊，点开是轻量浮层：技能浮层里勾选手册，规则浮层里查看始终生效的约束（内置与自定义），工具浮层里查看只读的工具清单；胶囊右侧是一个圆形的自动沉淀开关（默认关闭，星形图标，开启时底色加深，悬停显示说明），运行中收起，避免和暂停/终止挤在一起。打开技能或规则浮层时重新扫描对应目录，改完文件不需要额外按钮。

- 预览通过 `getDisplayMedia` 拉目标窗口视频流，只展示不响应点击；网格可开关，鼠标悬停显示对齐到 10px 的坐标。
- 时间线竖向串联每一步：截图缩略图、模型回复、工具调用与耗时；开始前有一条「已定流程」，模型宣布完成后有一条「最终核对」结果；长等待在条目里显示「已等待 00:30 / 05:00」的进度；缩略图点击看原始标注图。
- 运行中按钮为「暂停 / 终止」，暂停（含人工接管）时换成「继续 / 终止」。
- 控件语言：预览工具栏用无边框的幽灵控件（悬停淡墨底），开关默认描边、开启时整块填充墨色；配置与动作统一用胶囊形按钮，输入框保持 6px 圆角；主按钮深墨底，禁用态只留很轻的墨色，不抢视觉。
- 样式统一走 MUI 主题，不引入 Tailwind，不自研组件库。

## 10. 已知边界

| 边界 | 说明 |
|---|---|
| 技能匹配 | 只支持手动勾选，没有按任务自动匹配；现在只有一个示例技能 |
| 内置技能分发 | 打包后读 `userData/skills`，把内置技能复制过去的逻辑还没做 |
| 规则 | 始终加载、不参与勾选；不能关闭或覆盖内置规则，补充约束只能写进 `rules/*.md` |
| 断点续跑 | 未做，中断后只能从当前界面重新开始 |
| 全局停止热键 | 未实现，只能点界面「终止」；长等待也能被它打断 |
| Windows 前台激活 | `activateWindow()` 只在 macOS 生效，Windows 随打包一起补 |
| 键盘接管 | 只轮询鼠标，用户敲键盘不会触发自动暂停 |
| 暂停生效时机 | 步骤边界生效；`wait` / `wait_until` 执行中也能即时响应暂停与终止 |
| 等待上限 | `wait` 最多 1 小时；`wait_until` 只能等到当天时刻，跨天与每日重复未做（需定时任务） |
| 提问 | 没有超时，用户不在时任务会停在等待；一次只问一个问题，回答长度上限 2000 字 |
